# 戏境 AI 数字资产与 3D 模型工作台改造

请直接在当前 VS Code 打开的「戏境 AI」项目中实施本次前端改造。

我已经提供了一张数字资产与 3D 模型工作台的参考截图。请参考它的布局结构，但不要照搬其颜色、品牌、文案或其他视觉资产。

## 一、改造目标

把现有的数字资产与 3D 模型生成、查看区域整合成一个完整的三栏式工作台：

- 左侧：概念图、模型风格和生成相关设置。
- 中间：大面积 3D 模型查看区域。
- 右侧：已有数字资产库，以缩略图展示并支持选择模型。

整体颜色、字体、导航、按钮及页面背景必须与当前「戏境 AI」网站保持一致。

**参考图只决定布局，不决定配色。** 开始前先检查当前网页的主题色、共用 CSS、导航栏和工坊结构，不能直接将整个页面改成黑色主题。

## 二、左侧：模型操作区

将相关操作集中在左侧窄栏，避免功能分散在多个卡片和页面中。

根据现有真实功能，合理组织以下内容：

1. 概念图上传与预览。
2. Q版、写实两种风格选择。
3. 已有的模型参数与任务状态。
4. 必要的加载、错误和资源提示。
5. 清晰的操作入口及当前功能状态。

减少重复说明、开发测试提示和无实际作用的控件。未接入的功能不得伪装成可用功能。

### 建模安全限制

项目已经完成两个真实模型的生成与验收。用户已决定不执行第三次 Neural4D 建模。

因此：

- 保留现有建模功能的界面结构，但真实建模入口必须继续关闭。
- 不得调用 Neural4D，不得提交新的建模任务。
- 不得重置或修改全局建模额度记录。
- 如果保留生成按钮，应明确显示不可用状态及原因，不能让用户误以为点击后会实际生成模型。
- 可以继续选择、预览和查看已有资产。
- 不得因为调整 UI 而改变后端建模安全机制。

## 三、中间：3D 模型查看区

中间区域是整个页面的视觉中心，尽可能利用可用空间。

要求：

- 默认展示当前选中的已有 GLB 模型。
- 支持鼠标拖拽、触摸拖拽和缩放。
- 连续旋转能力至少达到 260°。
- 提供重置视角的操作。
- 正确展示 Loading、Ready 和 Error 状态。
- 模型加载失败时显示清楚的错误提示及恢复入口。
- 切换模型时正确更新当前资产，不出现旧模型与新模型混淆。
- 适当简化装饰性边框、说明卡片和重复按钮，让模型本身成为主视觉。
- 保留现有真实 GLB 加载、纹理兼容和错误恢复逻辑。

不得用静态图片代替真实 3D Viewer。

## 四、右侧：数字资产库

将已有数字资产集中放在右侧窄栏。

要求：

- 展示当前项目已保存的真实模型资产。
- 使用真实缩略图、角色名称、风格和必要的状态信息。
- 至少能选择现有的 Q版和写实两个模型。
- 点击资产后，中间 Viewer 加载对应真实 GLB。
- 明确区分已生成模型、待处理资产和不可用资源。
- 如果现有后端已提供资产列表接口，必须复用真实接口。
- 不得通过硬编码虚构资产或创建虚假的模型记录。
- 保留原有资产 ID、文件路径、Hash 和数据关联。

右侧面板可根据实际资产数量滚动，不要让资产库挤占中间模型查看区域。

## 五、整体布局与颜色

采用三栏工作台：

- 左侧操作栏：窄而清晰。
- 中间 Viewer：占据页面主要宽度。
- 右侧资产库：适度紧凑，便于快速切换模型。

桌面端优先保证三栏同时显示。

平板端可以收窄左右面板或折叠次要栏位；手机端改为纵向布局或可切换面板，不能直接压缩成无法操作的三栏。

视觉规范：

1. 从现有网站共用 CSS 中读取真实主题色和设计规范。
2. 继续使用网站现有的背景、品牌色、文字颜色、字体和按钮样式。
3. 不要复制参考图的黑色背景。
4. 不要大面积使用紫蓝渐变、发光描边或夸张动画。
5. 避免所有区域都做成独立卡片。
6. 保留现有导航栏、页面入口和已经完成的导航宽度优化。
7. 只改数字资产与 3D 工作台相关界面，不重做其他文化页面。

## 六、兼容现有项目

开始前检查当前 Git 分支、HEAD、工作区状态及现有代码。

优先复用现有组件、样式、后端接口和资产数据，不要为了布局调整重写整个项目。

必须保留：

- 原有 8 个 HTML 页面及其文化内容。
- DeepSeek 与 RAG 问答。
- 多 Agent 创作流程。
- Agent 历史档案与审校记录。
- 企业模式入口。
- 两个已验收的真实 GLB 模型。
- 当前 SQLite、Qdrant、BGE 和其他私有资源。
- 已有的错误恢复与安全降级机制。

不得初始化、清空、重建或迁移现有数据库及知识库。不得修改 `.env`、泄露 API Key、调用付费模型或产生外部 API 费用。

## 七、实际测试与验收

修改后必须实际测试：

1. 工作台布局符合三栏结构，颜色与网站现有主题一致。
2. 两个真实 GLB 均能加载。
3. 选择右侧不同资产后，中间 Viewer 正确切换。
4. 鼠标拖拽旋转至少 260°。
5. 缩放、重置视角正常。
6. Loading、Ready、Error 和错误恢复正常。
7. 桌面、平板、手机布局正常。
8. 8 个原有页面没有明显回归。
9. Agent、历史档案、问答和企业入口仍然可用。
10. 没有触发任何真实建模任务，现有资产及额度数据未改变。

不要把 Mock 测试当作真实模型验收。若无法执行某项测试，必须如实说明。
