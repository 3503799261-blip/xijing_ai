# Phase 4 Neural4D 安全边界与额度保护

初版日期：2026-10-11，更新日期：2026-10-12。本文依据当前 `backend/app/assets/usage.py`、`backend/app/assets/neural_service.py`、`backend/app/providers/neural4d.py` 和 `backend/app/api/assets.py` 的实际实现编写。测试记录与真实生成证据由阶段报告分别保存；本文不提供最终测试数量。

## 1. 当前执行边界

截至初版交付（2026-10-12文档提交93a57e2），Neural4D真实HTTP请求为0、真实建模提交为0。后续建模准备执行一次真实只读余额鉴权，见 [三次建模计划](../reports/phase-04-real-modeling-plan.md)；真实建模仍为0。供应商生成集成测试使用明确标识的 `httpx.MockTransport`，不能证明真实模型生成或扣费成功。

用户已在本地配置Key，并成功执行一次只读余额鉴权；这不证明建模权限或当前报价。本次建模实际Credit价格尚未核实。真实建模仍默认关闭；首次建模须展示角色、确认图片、Hash、冻结参数、用途、费用、额度，并取得单次明确授权。

开发批准不等于真实建模授权。余额验证不创建模型，也不能单独证明账号具备建模权限。后续实际余额查询单独记为供应商HTTP请求，不算新建模型尝试。

## 2. 全项目固定账本与三次硬限制

生产账本固定为 `WORKSPACE_ROOT/.runtime/neural4d-usage.sqlite3`，在当前工作区对应 `D:\京剧\.runtime\neural4d-usage.sqlite3`。它位于静态网站目录之外，独立于 `RAG_DATA_DIR`、角色ID、风格、企业模式和供应商Key。

固定政策为全项目累计最多 **3次新建模型任务的HTTP提交尝试**，每次固定 `modelCount=1`。它计数提交尝试，不以成功模型数量计数；Q版和写实共用同一额度。代码常量、SQLite约束、插入触发器和事务内检查共同限制上限，没有环境变量、公开重置接口、自动返还或提高上限的方法。

默认真实HTTP Provider在构造和每次创建之前检查固定账本路径。不同的真实或自定义HTTP transport不能通过临时目录、应用工厂override或新建UsageManager重置全项目额度。只有明确的 `httpx.MockTransport` 可使用隔离的测试账本。

账本应与项目运行数据一起保存、备份和审计。程序内的不可变约束保护应用操作；账本文件的安全保存仍依赖本地文件权限和运维管理，不能通过删除、替换或回滚文件规避项目约定。

## 3. 历史未知时关闭创建

新账本或丢失后重新建立的账本以未知历史开始，`historicalUsageVerified=false`，历史占用、全项目已使用次数和剩余次数为 `null`，不会自动登记为0。

**本地创建记录为0，不等于全项目历史提交为0。** 需要核查此前开发记录、供应商记录及用户确认后，才能通过可信的一次性CLI登记历史占用。`backend/scripts/neural4d_history.py` 要求明确次数、脱敏核查说明及 `--acknowledge-project-history`；它不是网页接口，登记后不可重复初始化或降低历史次数。本轮没有凭测试结果或本地空表自动完成历史登记。

已核实历史后的占用计算为：

```text
全项目占用 = 已核实历史提交尝试数 + 当前账本全部创建记录数
剩余次数   = 3 - 全项目占用
```

`RESERVED`也占用额度；失败、未知、待核查和成功记录均保留。摘要中的 `used_attempts` 与 `reserved_attempts` 分开展示，而限额判断使用 `occupied_attempts`，不能用已成功任务数量代替。

## 4. SQLite原子预留与发送权

所有真实建模使用 `ModelService.submit → UsageManager.reserve → Neural4DProvider.create_once` 同一入口。浏览器不接触供应商Key，也不直接调用供应商；Agent流程没有绕过此入口创建模型的通道。

`reserve()` 使用 `BEGIN IMMEDIATE`，在同一事务内核对固定政策、历史、剩余额度、一次性批准、批准有效期、幂等键及冻结输入Hash，插入 `RESERVED` 并消费批准。SQLite唯一约束保护幂等键和单次批准；数据库插入触发器再次拒绝未知历史和第四条创建记录。

随后 `mark_started()` 用另一个原子事务从 `RESERVED` 转为 `ATTEMPT_STARTED`，先持久化发送领取时间与审计事件，再进行HTTP提交。只有领取成功者可以发送；第二个线程、进程或重放不能再次领取。同一全项目owner文件锁确保服务恢复和生产发送由一个实例管理，未取得owner锁的实例不能完成真实建模门禁。

事务不会跨越网络等待。数据库使用外键、忙等待超时与 `synchronous=FULL`；账本异常时返回脱敏错误并拒绝创建，而不是退回内存计数。

## 5. 人工批准、鉴权与冻结输入

供应商操作接口要求独立的 `X-Asset-Admin-Token`，后端使用恒定时间比较校验本地管理令牌。令牌不写入Git、URL、截图、业务日志或浏览器持久存储。供应商Key只由服务端私有配置读取。

创建还必须同时满足真实建模启用开关、供应商协议核验、独占owner锁、有效的近期余额核验、费用配置、已核实历史及剩余额度。启用开关和持有Key不能代替用户单次批准。

单次批准默认有效15分钟、只消费一次，绑定服务端冻结的输入及用途：

- `assetId`、`assetVersion`、`characterId`、`styleMode`、`styleVersion`；
- 原Phase 3结果Hash和文化引用Hash；
- 已确认的 `imageId`、图片Hash、PromptHash；
- 服务端选择的供应商参数、固定 `modelCount=1` 和本次用途。

预计Credit另存于不可编辑的批准记录中。未发送任务提交前必须与当前已配置预计费用完全一致；费用变化或重新变为未知时拒绝提交，要求重新核实并确认。该预估是人工核验的应用配置，不是供应商扣费承诺，也不是账户硬扣费上限。

提交前重新读取Phase 3权威任务、核对人工确认和审校结果，并验证角色结果Hash、图片文件实际Hash、Prompt确认、图像接受状态、版本和用途。客户端不能选择任意供应商参数；旧批准缺少风格与角色版本绑定时不能按新参数继续发送。

## 6. 幂等、Prompt版本与历史任务

同一幂等键仅能绑定同一批准ID、完整冻结输入Hash和用途；相同键携带其他图片、风格或批准返回冲突。

对于已经领取发送权的同键重放，只返回原尝试记录，绝不再创建任务。即使后来编辑Prompt或修改预计费用，原任务的版本与费用仍作为历史记录保留。只读重放不会消费新次数，不能被用来发送另一份输入。

新的Prompt版本使同一版本分支的旧未发送批准失效。分支与资产目录实际递增规则一致：`sourceTaskId/sourceResultHash/styleMode/mode/purpose/enterpriseBrief`。冻结前从完整资产目录检查最新版本，不依赖仅展示最新100条的公开列表。Q版更新不会使写实分支批准失效；用途或企业简报不同的分支也保留独立版本。

自由编辑的全文Prompt保存为不可覆盖的新草稿，带 `culturalReviewRequired=true`，不能仅凭视觉确认解除文化门禁；需经真实Agent重新审校并人工确认新的角色任务。服务端固定风格模板复用已确认Phase 3文化依据，不把风格模板选择冒称为新增文化专家审核。

历史任务的状态查询、下载与模型溯源不受最新Prompt门禁影响，仍关联原批准、原图像和原文化引用。

## 7. 失败、超时与重启

2026-10-12建模准备修复新增全局可核查暂停（e371019）：任意`UNKNOWN/PENDING_RECONCILIATION`使所有角色/风格的批准、预约和未领取发送权任务暂停；三个写事务内重查，summary暴露`creationPaused/pauseCode/unreconciled_attempts`。已发送同键只回读、原任务查询仍可使用。可靠核查恢复已知状态后可解除临时锁，不退款、不自动发送；各次顺序和人工验收仍由明确确认记录执行。此修复前初版仅阻止相同输入重建，真实失败与修复证据保留在三次计划中。

| 情况 | 本地处理 | 是否返还或自动重建 |
| --- | --- | --- |
| 明确HTTP拒绝，如400/401/402/403/422/429 | `FAILED`，保留提交尝试 | 否 |
| 超时、5xx、重定向、解析失败、响应不明确 | `UNKNOWN`，保留提交尝试 | 否 |
| UUID数量异常或相互冲突 | `UNKNOWN`并持久化停止新建标记 | 否 |
| 可能已发送但本地保存失败或协程取消 | 保留领取记录、标记未知或停止新建 | 否 |
| 重启发现 `RESERVED/ATTEMPT_STARTED/UNKNOWN` | owner锁内转为 `PENDING_RECONCILIATION` | 否 |
| 已知可靠UUID的 `SUBMITTED/PROCESSING` | 保留原UUID，可主动查询原任务 | 否 |

即使重启时只有 `RESERVED` 而没有发送时间，也采取保守占用，不能自动补发或返还。已领取发送权、事件记录、冻结参数、历史政策和供应商UUID有不可变数据库保护。

未知结果先通过供应商记录或人工方式核查；没有可靠UUID时，本地刷新接口明确拒绝查询并提示核查。当前未实现自动供应商历史补录、自动未知状态修复或自动再生成。已明确失败后，如用户要求重新创建，必须再次人工批准，使用新批准和新幂等键，并占用剩余次数；未知或仍在进行的相同输入禁止换键重建。

## 8. 当前供应商协议与双风格参数

当前实现依据2026-10-11核对的官方管理API：

- 文档索引：[Neural4D文档目录](https://docs.neural4d.com/llms.txt)；
- 接入说明：[官方Quickstart](https://docs.neural4d.com/en/quickstart)；
- 图生3D参考：[官方图生3D接口](https://docs.neural4d.com/en-api-reference/image-to-3d/generate-model-with-image)。

实际图生3D创建采用 `POST https://alb.neural4d.com:3000/api/generateModelWithImage` 的multipart输入，上传已实际解码和规范化的PNG图片。不使用旧PDF描述的JSON `fileKey`路径，不自动尝试备用建模接口。

| 参数 | Q版 `chibi` | 写实 `realistic` |
| --- | --- | --- |
| `modelCount` | 1 | 1 |
| `mesh_quality` | standard | standard |
| `faceNum` | 100000 | 500000 |
| `disablePbr` | 0 | 0 |
| `onlyGenerateMesh` | false | false |
| `enableImageEnhancement` | false | false |

两种风格使用同一个普通图生3D接口，区别来自已确认风格Prompt、概念图和服务器几何密度预设。面数不能保证艺术风格，不声称图片会原样生成。不使用可能产生多候选的专用Q版接口；其价格和单模型保证未在本轮核验。

HTTP transport关闭自动重试、自动重定向和环境代理继承。UUID响应必须能确认唯一模型；异常时不能换参数重发。当前价格须在真正提交前依据最新供应商文档或账户报价核查，文档中的离线测试费用数字不能当作真实报价。

## 9. 查询节流、下载与GLB边界

余额查询使用 `queryPointsInfo`，检查严格整数成功标识和有效非负余额；返回200本身不等于验证成功。生成状态使用原UUID调用 `retrieveModel`；`codeStatus`严格校验整数，分别处理进行中、成功和失败，布尔值、字符串及未知状态不会被当作完成。

没有自动轮询。主动查询原任务必须通过管理员鉴权，SQLite持久化以下限制：同一任务至少间隔15秒；一轮最多20次或20分钟。达到限制后必须明确确认继续查询；继续查询只重置本轮计数，保留累计计数，绝不创建模型。

供应商下载URL须为HTTPS，主机位于人工核验的白名单内，不允许用户信息、其他端口或任意外链。真实下载检查DNS地址为公网；不向签名对象存储URL发送供应商Authorization，不自动跟随跳转。下载最大50MB，有超时和错误提示。DNS检查与连接并非固定IP绑定，不将此边界宣称为完整生产SSRF防护。

下载后必须通过GLB结构与可加载资源检查才能登记成功；HTTP200或 `.glb` 后缀不能证明文件有效。模型保存在静态目录外，以登记ID经后端提供文件、下载与Range请求。模型元数据关联原资产、概念图Hash、供应商UUID和文化来源Hash；用户看到的公开记录不暴露供应商签名URL、内部路径或密钥。

当前接受可独立加载的GLB；未实现自动付费格式转换。供应商返回其他格式或未核验下载主机时，先明确失败并人工处理，不能擅自调用转换或备用生成接口。

## 10. Mock隔离与证据区分

常规离线供应商测试显式注入 `httpx.MockTransport`，使用临时SQLite、测试管理员令牌和标注为假的供应商Key。测试禁止真实DNS；常规应用工厂测试通过测试专用注入拒绝任何意外供应商请求。生产工厂没有新增任意HTTP transport配置入口。

记账分类测试另使用完全在内存中响应、没有HTTP连接或socket行为的自定义transport，并临时替换测试的canonical路径。其临时账本会刻意记为 `is_mock=0`，验证任意自定义transport不能冒充标准Mock来跳过固定账本和公网地址检查；这些测试临时记录不构成项目真实调用或真实生成证据。生产分类、创建日志和下载DNS检查统一只将 `httpx.MockTransport` 视为Mock。

离线创建、余额、UUID和下载响应都是合约样例。操作日志保存 `is_mock`、请求类别、脱敏错误码、状态、耗时及可确认的费用字段；不保存Authorization、真实Key或完整签名URL。普通查询/下载请求数量与创建尝试额度分别记录，Mock数量与真实请求数量分别统计。

可合法使用已有GLB验证Viewer交互，但已有测试模型不代表本项目角色已经经Neural4D建模。真实生成成功证据只有在用户单次授权、供应商实际调用、唯一任务ID、有效模型文件、真实浏览器验收及脱敏日志全部完成后才能补录。

## 11. 首次真实提交前的停止检查

首次生成准备完成时必须停止，向用户提供以下具体内容，不自行提交：

1. 已确认Phase 3角色与文化来源、当前风格及最新资产版本；
2. 已确认概念图、图片Hash、PromptHash及本次用途；
3. 本文服务器参数、当前官方协议核对结果；
4. 实际Key/权限与只读余额验证结果；
5. 经核实的单次预计Credit和费用变化检查；
6. 经核实的全项目历史、当前占用和剩余次数；
7. 已完成的离线额度、并发、幂等、失败恢复、GLB及Viewer测试；
8. 超时仍占次数、结果未知须人工核查等风险。

只有用户针对该次模型明确批准，并通过服务端所有门禁，才可发送一次创建请求。最终阶段仍停在检查点B，不能自动进入下一阶段。
