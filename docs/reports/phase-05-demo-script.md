# 戏境 AI · 比赛演示讲稿与操作脚本

编写日期：2026-10-22（Asia/Shanghai）。交付范围：Phase 5 WP5文档材料，不新增业务功能，不执行演示或付费调用。

本稿按当前代码与已保存证据编排。**约7分05秒标准版、约3分钟精简版均是新讲稿的预计时长，尚未进行真人口播排练、录制或成片验收。** WP4实际完成的是自动化浏览器排练：正常10步300.071秒、故障4步40.038秒，包含脚本规定的阅读停留，不等于真人已完成本稿。原结果见[排练JSON](../evidence/test-results/phase-05-wp4/rehearsal.json)及[WP4原始测试报告](../evidence/test-results/phase-05-wp4-test-report.md)。

5～8分钟、1080p MP4和不少于2分钟AI协作开发来自[用户历史需求](../prompts/phase-01/00-original-user-request.md)，本稿据此安排准备内容；比赛正式名称、格式、截止和官方提交规则仍待补充，不宣称已经满足官方视频要求。详见[比赛要求对应表](phase-05-requirements-evidence-map.md)。

## 1. 演示范围和公开门禁

默认路线为**免费本地操作＋同一真实历史任务＋已保存写实GLB**。整场不发送新问答、不创建或确认Agent任务、不登记新资产、不调用图像生成或Neural4D。查看历史不是重新运行，查看已有GLB不是重新建模。

公开演示前先核对[素材来源与权限](phase-05-asset-provenance-and-permissions.md)：

- 第1个Q版仅获内部非公开技术验证范围，`publicationAllowed=false`；不能直接放入公开视频、公开路演或公开资源包。它没有正式Phase 3角色关联，也不是“绛绣·戏韵”的Q版版本。
- 写实模型有用户确认的比赛展示、上传与衍生用途声明，但作者、原始页面及许可凭证仍未独立核实，不能由此推出商业销售或公开GLB再分发许可。**公开录制/提交前仍需补齐所需权限依据；不能用“百度公开资源”代替授权。**
- 原网页图片、视频、字体等也须按权限清单逐项核对。无法确认的视觉材料不进入公开成片；可以改讲脱敏的流程、代码和测试证据，保留受限模型在内部受控环境验收。
- 本稿列出的页面和模型是本机入口，不是已发布的公网服务。不要把私有库、概念图、GLB、签名下载URL或环境配置随讲稿公开。

以下“公开主线”是权限补齐后的建议路线，不表示WP5已取得新的公开许可。存在许可缺口时，内部排练可按既有授权范围查看，公开提交依[最终检查表](phase-05-submission-checklist.md)保持PENDING/BLOCKED。

## 2. 演示前准备：由操作员完成，不计入口播

1. 核对交付提交、分支及工作区，按[部署与恢复指南](phase-05-deployment-and-recovery.md)准备已有Python环境、本地BGE/索引、原Agent与资产记录、两个原GLB及固定额度账本。Git克隆不包含这些私有成品资源；不要在现场首次下载模型或凭空初始化一个“空历史库”。
2. 用指南中的单worker命令启动本地HTTP应用，待startup complete后再打开页面；不重复启动第二个worker、不杀未知进程、不删除owner锁。错误路径或损坏数据库按恢复说明处理，恢复后重启；不能为了演示建空库替代旧数据。
3. 手动进入[工坊导览](http://127.0.0.1:8000/about.html#ai-workshop-demo)，点击“进入只读备用演示”，再按需点击“检查本地演示条件（免费）”。四项只读GET不探测外部供应商；绿色条件不代表今天DeepSeek可用，也不代表GLB已经加载。
4. 备用保护只在当前页面生效，刷新/新页不继承，且不会停止已经存在的后台任务。演示前确认没有正在执行的真实任务；新页只浏览指定Viewer，不触碰问答、Agent提交、确认、取消、导入或登记。要在新工坊页使用保护，重新进入该页备用模式。
5. 只读核对额度显示已用2/3、剩余1次未使用、第三次由用户取消、创建关闭。剩余1次不是调用授权；不做供应商余额、结果刷新、创建拒绝探针或任何新建模HTTP请求。
6. 准备两个浏览器页签：工坊导览/历史；已有写实资产。内部评审另可准备受限Q版页签，公开视频不得带入。关闭私有env、含凭证终端和无关个人页面；核对待展示的历史需求、JSON与截图没有个人敏感信息。
7. 本次WP5不重新执行上述启动或浏览器动作。既有实际验证和未完成项目见[证据索引](phase-05-evidence-index.md)，不能口播成“刚才已经重新通过”。

## 4. 标准版：约7分05秒，默认无付费请求

以下时间是讲述分配，真实加载、阅读和现场说明会有变化。发现错误先如实说明，再使用第7节备用路线；不要用旧成功记录覆盖当前失败。

### 00:00–00:25 · 从文化网站进入项目（25秒）

- **类型/目标**：实时本地页面＋项目说明；说明对象和问题。
- **页面/操作**：首页→导航“AI戏韵工坊”，或直接工坊导览；不播放未经公开核对的旧媒体。
- **预期画面**：原8页文化站的视觉语言、AI工坊标题与真实功能入口。
- **口播**：“戏境AI从京剧文化展示网站逐步升级。我们想让文化学习、角色创作和数字资产展示之间有可核查的联系：先查资料，再协同设计，由人决定是否接受，最后查看已经保存的3D成果。”
- **依据**：[WP1流程](phase-05-work-package-01.md)、[8页/真实GLB浏览器证据](../evidence/test-results/phase-05-wp4-db-repair/normal-model-browser.json)。
- **依赖/费用**：本地HTTP和静态资源；无外网LLM，无API费用。
- **故障备用**：页面未打开时说明本地服务问题，按部署指南检查；只能展示已核对的历史截图并标注“历史截图”，不能说当前页面运行正常。

### 00:25–00:55 · 导览与RAG入口（30秒）

- **类型/目标**：实时本地导览＋静态功能说明；展示问答使用边界。
- **页面/操作**：导览“进入只读备用演示”→第2步→“前往这一步对应的功能”；可点击推荐问题填入，但不发送、不重试。
- **预期画面**：问答说明、输入框、引用位置；没有新的AI回答。
- **口播**：“问答由后端先做本地BGE向量和关键词混合检索，再将筛选出的资料交给DeepSeek解释，引用映射回本次真实片段。资料不足时不会补造来源。今天这段采用免费历史路线，不发送新的付费问题；下面看原任务保存的研究依据，它不是一条新的聊天回答。”
- **依据**：[Phase 2真实测试与限制](phase-02.md)、[RAG协作演进](../prompts/phase-02/04-development-evolution.md)、[WP3原始测试](../evidence/test-results/phase-05-wp3-test-report.md)。
- **依赖/费用**：静态问答界面可读；实际问答另需BGE/索引、后端、外网LLM及授权费用。本步0调用。
- **故障备用**：健康未就绪不强行发送；进入历史Research。没有独立聊天历史就明确没有保存，不能临时填一段假答案。

### 00:55–01:45 · 看同一真实Agent任务及RAG依据（50秒）

- **类型/目标**：真实历史任务查看；讲清四阶段协作和证据。
- **页面/操作**：导览第3步“填入绛绣历史ID（不自动读取）”→手动“读取历史记录”→“查看只读详情”。展开“Agent执行顺序与公开阶段产物”中的任务规划和京剧研究，再展开“历史RAG研究依据”的一条引用；保留任务ID、保存时间和“只读快照”标签。
- **预期画面**：绛绣原任务的Planner、Research、Designer、Reviewer记录及保存的来源ID、定位、摘要。只展示已保存内容，缺字段显示未保存。
- **口播**：“这是之前保存的真实任务，不是刚刚运行。任务规划确定创作边界，Research复用真实RAG检索；角色设计和文化审校再依据这些结果处理。引用记录能追到具体来源和片段，但项目摘要不是原网页全文，AI辅助审校也不是专业戏曲专家认证。”
- **依据**：[WP2报告](phase-05-work-package-02.md)、[WP2原始测试](../evidence/test-results/phase-05-wp2-test-report.md)、[第二次真实角色流程](phase-04-second-model-execution.md)。
- **依赖/费用**：本地后端、原Agent库；查看来源外网页面才需要外网，本稿停留在本地保存摘要。只读GET，0付费。
- **故障备用**：无记录则核对ID/筛选；503则展示真实错误，不换新库、不重跑。转现有资产或脱敏历史报告；不把不同任务拼接为一个成功任务。

### 01:45–02:25 · 角色JSON、文化审校与人审（40秒）

- **类型/目标**：同一真实历史结果；区分设计、有据事实和用户决策。
- **页面/操作**：仍在同任务，展开“查看已保存的角色与结果JSON”“查看已保存的文化审校”“查看已保存的人工确认记录”；只读资产关联中的写实asset/model ID。
- **预期画面**：绛绣原创设定、一般文化资料引用、AI辅助审校pass及已保存的用户接受记录；不是一键自动授权所有第三方素材。
- **口播**：“绛绣·戏韵被定义为原创京剧风格角色，不强行称为某位传统人物。服饰创作与资料支持的文化事实分开记录。AI审校之后仍需要人接受这份具体方案；角色JSON、人审和3D资产各有自己的记录，只有已建立真实关联才显示模型。”
- **依据**：[新方案审核](phase-04-second-role-v2-review.md)、[用户原接受记录](../prompts/phase-04/22-second-role-human-acceptance.txt)、[WP2历史渲染实现](../../js/ai-workshop/agent-history.js)。
- **依赖/费用**：本地Agent库及关联资产库；只读，0付费。
- **故障备用**：缺字段保留“历史记录未保存该信息”；不能当场补写或代用户确认，也不能将一般行当资料说成全部头饰/服饰的鉴定结论。

### 02:25–03:20 · 已保存写实GLB与交互（55秒）

- **类型/目标**：已保存的真实3D资产＋实时本地Viewer；展示真正的空间交互。
- **页面/操作**：点击历史详情中的“只读查看已有资产与Viewer”，核对绛绣asset/model身份；观察Loading→Ready。鼠标在模型区连续分段同向拖动，实际观察正面、侧面和背面，总范围至少260°；滚轮及“放大＋/缩小−”，点击“重置视角”。如有余时，切Q版显示未生成，再切回写实原模型。**不要点击下载、登记、导入或建模。**
- **预期画面**：原真实GLB可旋转、缩放、重置；绛绣缺Q版时清晰空态。当前度数以现场实测为准，不能将旧证据数值冒充这次测量。
- **口播**：“这是第二次历史Neural4D任务保存的写实模型，现在只从本地加载，不会重新生成。模型可以从不同方向查看。细珠饰可能简化，背面由单图推测，袖布可能遮挡；它通过了约定技术验证，不等于完成骨骼动画、游戏生产规格或文化专家审定。”
- **依据**：[两模型最终验收](phase-04-final-acceptance.md)、[WP4数据库修复后模型回归](../evidence/test-results/phase-05-wp4-test-report.md)、[model-viewer适配](../../js/ai-workshop/model-viewer-adapter.js)。
- **依赖/费用**：本地后端、资产目录、原GLB及本地Viewer库；GLB纹理内嵌，无新外部AI请求。公开展示先满足第1节许可门禁。
- **故障备用**：Error时只点“重新加载原模型”，保持同一ID；仍失败说明当前失败，展示已核实的技术记录。不得刷新供应商任务、重新建模或用Duck冒充绛绣。

### 03:50–05:50 · 真实AI协作与失败修复（120秒）

- **类型/目标**：历史开发证据，不是新对话或实时开发；让评委看见方案如何被验证和修正。

- **口播**：“这些是开发时真实保存的过程。RAG经过检索与引用修正；原创角色曾被误作传统实体而暂停，用户批准修改需求后重跑；模型曾因下载和纹理兼容失败而恢复原文件。我们保存失败再复验，不把历史成功包装为当前重新执行。”
