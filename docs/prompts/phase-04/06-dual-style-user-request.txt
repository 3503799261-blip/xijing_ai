# 戏境 AI — Phase 4 双风格角色生成补充开发指令 V1.0

你现在继续执行「戏境 AI」Phase 4开发。

本次是对已经批准的Phase 4开发任务进行功能补充，不是重新设计整个项目，也不是启动新阶段。

**核心新增需求：平台必须支持用户自由选择Q版（Chibi）与写实（Realistic）两种京剧角色风格。**

必须保持Phase 1～3现有功能完整，并严格遵守Phase 4原有的Neural4D API调用限制、3D Viewer验收标准和比赛证据要求。

## 一、双风格功能目标

目前Phase 3已经能够完成：

用户创作需求 → Planner → Research（真实RAG）→ Designer → Culture Reviewer → 人工确认 → 角色JSON。

Phase 4需要增加风格选择层，使同一套京剧文化角色设定能够生成不同视觉风格的数字资产。

新增流程：

用户提出角色需求

→ 多Agent文化研究与角色设计

→ 文化审校

→ 统一角色设定JSON

→ 用户选择Q版或写实风格

→ 对应风格的视觉Prompt

→ 对应风格的概念图

→ 人工确认

→ Neural4D图生3D

→ 网页3D Viewer展示

要求：

1. 用户可以自由选择Q版或写实。
2. 两种风格使用同一套文化研究依据。
3. 风格变化不能随意修改角色行当、服饰文化依据或文化审校结论。
4. 两种风格对应不同的概念图Prompt和3D生成参数。
5. 不能把风格切换按钮直接绑定到Neural4D真实建模请求。
6. 同一角色可以保存多个风格版本，但没有生成的模型不能伪装成已有3D资产。

## 二、角色资产层扩展

在现有Phase 4 Character Asset Schema基础上扩展，不得破坏Phase 3数据协议。

新增核心字段：

- `style_mode`：视觉风格，支持`chibi`、`realistic`。
- `style_version`：当前风格配置版本。
- `character_id`：统一文化角色ID。
- `asset_id`：当前风格资产ID。
- `culture_basis`：引用Phase 3文化研究结果。
- `character_design`：角色核心设定。
- `visual_prompt`：当前风格的概念图Prompt。
- `reference_image`：当前风格的概念图资产。
- `model_asset`：当前风格的3D模型资产。
- `generation_status`：资产生成状态。

字段命名与具体结构应优先兼容现有项目，不要重复创建功能相同的Schema。

需要建立：

**一个Character对应多个Style Asset版本。**

例如：

同一个角色：

青衣少女·云绮

其下可以具有：

- Q版资产
- 写实资产

两种资产关联同一套文化资料，但图片、Prompt及3D模型分别管理。

不得因用户切换风格而覆盖另一个风格版本的模型文件。

## 三、Q版风格设计

风格代码：

`chibi`

前端名称：

**Q版卡通**

视觉特征：

- 大头小身体比例。
- 可爱、鲜明、易识别。
- 保留京剧行当和脸谱文化元素。
- 适度简化复杂头饰、珠串与戏服结构。
- 保留具有文化辨识度的服装配色。
- 适用于文旅吉祥物、游戏NPC和数字IP形象。

概念图Prompt要求：

- 单人物完整全身。
- 轮廓清晰。
- 面部与头饰完整。
- 手臂适度离开身体。
- 简洁背景。
- 不包含文字、拼贴和水印。
- 注重三维建模友好的形体结构。

不可为了卡通化而改变文化符号的原本含义。

## 四、写实风格设计

风格代码：

`realistic`

前端名称：

**写实国风**

视觉特征：

- 接近真实人物的身体比例。
- 京剧服饰纹理与刺绣细节更加丰富。
- 头饰、流苏、冠饰具有精致材质表现。
- 合理表现布料层次与传统配色。
- 适用于游戏角色、文化数字人及影视概念角色。

概念图Prompt要求：

- 单人物完整全身。
- 姿态自然，人物比例合理。
- 头饰与鞋履完整可见。
- 服装结构清楚。
- 背景简洁。
- 避免过度遮挡。
- 尽量控制容易导致图生3D失败的复杂细小悬挂结构。

写实风格应优先保证人物比例、文化服饰结构和材质表达，而不是盲目增加装饰复杂度。

## 五、前端风格选择器

在现有「AI戏韵工坊」的角色资产或数字IP区域新增风格选择器。

至少包含：

**Q版卡通 | 写实国风**

交互要求：

1. 用户可以在两种风格之间切换。
2. 切换后更新当前风格说明。
3. 切换后更新视觉Prompt预览。
4. 如当前风格已有概念图，展示对应图片。
5. 如当前风格已有3D模型，展示对应GLB。
6. 如果没有模型，明确显示“当前风格尚未生成3D模型”。
7. 风格切换不得触发付费API。
8. 已经通过人工确认的概念图若因风格修改而发生变化，必须重新确认。
9. 已生成的Q版和写实资产不得相互覆盖。

界面必须保留网站原有酒红、金色及米白色设计体系。

中文优先，字体与按钮大小要适合比赛投屏展示。

## 六、视觉Prompt生成模块

采用统一文化角色设定 + 风格模板的方式。

不要为两种风格建立完全独立的Agent工作流。

推荐：

Phase 3 Character JSON

→ Style Adapter

→ Q版Prompt / 写实Prompt

→ Concept Image

要求：

- 两种模板明确分离。
- 文化研究结果统一复用。
- 支持Prompt版本记录。
- 支持人工编辑Prompt。
- 记录使用的角色ID、风格和文化依据。
- 不允许随意编造新的京剧文化事实。
- 若风格调整引入新的文化元素或明显改变原文化表达，应重新进行必要的文化审校。

## 七、概念图管理

当前图像生成API供应商尚未完全确定。

因此：

1. 优先支持用户上传拥有使用权的概念图。
2. 预留独立的图像生成Provider接口。
3. 在供应商确认之前，不调用真实付费图像生成API。
4. 两种风格都必须能通过Mock或合法测试图片完成流程。
5. 保存图片来源、许可说明、文件Hash和关联的风格版本。
6. 禁止使用未经许可的第三方角色图片作为正式比赛资产。

概念图需要经过人工确认后才可以进入真实3D建模环节。

## 八、Neural4D额度保护

原有硬限制不变：

**整个项目最多3次Neural4D真实新建模型HTTP提交尝试。**

包括测试、调试和最终建模。

必须继续遵守：

- SQLite原子预留。
- 幂等与并发保护。
- 单次创建一个模型。
- 默认关闭真实建模。
- 人工逐次批准。
- 未知结果不自动返还额度。
- 禁止自动重试新建任务。
- 前端不得直接访问Neural4D。
- Agent不得绕过服务层创建任务。

重点：

**Q版与写实共用整个项目的3次全局配额，不是每种风格各有3次。**

用户切换风格、重新生成Prompt、上传图片、查看已有模型，都不能自动调用Neural4D。

必须记录每次真实建模使用的风格、角色、Prompt版本、图片Hash及任务ID。

当前没有收到真实建模的逐次调用授权，不得自行使用任何额度。

## 九、3D Viewer兼容性

继续使用已经批准的`model-viewer + GLB`方案。

Q版与写实都必须支持：

- 鼠标拖拽旋转。
- 手机触摸拖拽。
- 至少260°连续水平旋转观察。
- 优先360°自由水平旋转。
- 鼠标滚轮缩放。
- 双指缩放。
- 缩放按钮。
- 重置视角。
- Loading状态。
- Ready状态。
- Error状态。

切换两个风格时：

如果存在对应GLB，正常加载。

如果没有对应GLB，显示清晰的未生成状态。

不得使用静态图片或GIF冒充3D模型。

不得使用同一个模型假装成两种不同的真实生成结果。

## 十、个人模式与企业模式

个人模式：

支持文化体验、京剧角色创作与Q版/写实自由选择。

企业模式：

允许根据应用场景选择风格。

例如：

文旅吉祥物 → Q版优先。

游戏角色 → 写实或Q版按需求选择。

不得将风格与用户类型强制绑定。

两个模式都必须使用相同的文化研究、文化审校及API配额安全机制。

## 十一、测试要求

新增双风格专项测试，至少覆盖：

1. Q版风格选择。
2. 写实风格选择。
3. 风格切换不触发真实API。
4. 同一角色保持相同文化依据。
5. 两种Prompt模板正确生成。
6. 原Phase 3角色JSON兼容。
7. 两种风格的图片分别保存。
8. 两种风格的GLB分别保存。
9. 缺少模型时显示未生成状态。
10. 错误模型时显示Error。
11. 已有GLB正确加载。
12. 鼠标拖拽至少260°。
13. 手机触摸交互。
14. 缩放和重置视角。
15. 风格修改后人工确认失效与重新确认。
16. 全局3次额度不会按风格分别计算。
17. 并发及重复点击无法绕过全局限制。
18. 原8个京剧网页回归正常。

Mock测试必须与真实API调用测试严格区分。

不得伪造真实生成成果或浏览器测试结果。
